# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Bobby Muljono's personal portfolio site (deployed on Vercel) — About/bio, selected project write-ups, and a live AI persona chatbot ("Bobby AI"). A blog is the remaining Phase 2 item (see `TODO.md`).

## Commands

Requires Node >=22.12.0.

- `npm install` — install dependencies
- `npm run dev` — start the Next.js dev server at `localhost:3000` (`next dev`; port moved from Astro's `4321`)
- `npm run build` — `next build`: type-checks and builds the site (static/SSG pages, plus the `/api/chat` and `/api/contact` route handlers bundled as serverless functions)
- `npm run start` — `next start`: serve the production build locally (replaces the old `npm run preview`)
- `npm run lint` — `next lint`
- `npm run ingest` — re-chunk + embed `knowledge/` + published write-ups (read from `content/projects/`, `.md` and `.mdx`) into Supabase pgvector (run after editing the chatbot KB; reads secrets from `.env`)
- `npm run pdf2md` — KB-prep helper (dev-only, not shipped): extract a PDF into a draft `.md` in `knowledge/_staging/` for human review before it ever reaches the ingest pipeline. No-arg form converts every `*.pdf` in the project root then deletes the source from the root; `npm run pdf2md -- <path>` targets a specific PDF (never deleted unless it sits in the root); `--dry` previews without writing, `--keep` skips deletion. See `scripts/pdf-to-md.mjs`. **The ingest pipeline stays markdown/MDX-only** — this is a deliberate staging step (extraction is noisy: bullets flatten, headers/footers need trimming), so promotion from `knowledge/_staging/` into `knowledge/` is a manual, reviewed decision. `knowledge/_staging/` and root `*.pdf` are git-ignored.

There is no test suite. Running the chatbot in `npm run dev` requires a local `.env` (copy `.env.example`).

## Session workflows

Two named routines the user triggers by phrase. Treat any close paraphrase as the trigger (e.g. "let's start", "kick off", "spin up" → **start**; "prep handover", "wrap up", "hand off" → **prepare handover**).

**Branching for larger phased work (added 2026-09-01):** for work that spans multiple phases (e.g. a framework migration), use targeted branches per phase, `feature/…`, `bugfix/…`, `docs/…`, distinct from the `session/<date>` bootstrap branch above. Stack each phase branch on a shared `feature/<name>-migration` integration branch, then do a single cutover merge to `main` once all phases land. Example: the Astro to Next.js migration used `feature/nextjs-migration` as the integration branch (with a `docs/nextjs-migration` docs pass stacked on it); it was fast-forward-merged to `main` on 2026-09-01 and both branches are now retired.

### Sub-agent routing (auto-delegate)

Standing instruction from Bobby (2026-07-11): **automatically delegate the mechanical tasks below to their sub-agents** (`.claude/agents/`), without waiting to be told to use them by name. This is a durable, pre-authorized request to spawn, so treat these task types as an exception to the "don't spawn unless asked" default — the ask is standing, right here.

- **Git routines → `git-ops` (Haiku).** The session-start git bootstrap (step 1 below), the git half of "prepare handover" (stage/commit/push, step 2 below), and any ad-hoc git command the user asks for (pull, status, branch, commit, push). Hand it the specifics it needs (today's date, the exact commit message). **Keep on the main thread:** deciding *what* to commit and *writing* the commit message — the agent executes, you supply intent.
- **Chatbot KB rebuild → `kb-ingest` (Haiku).** After `knowledge/` files are edited or a write-up is published (`draft: false`), delegate the `npm run ingest` + verify cycle. **Keep on the main thread:** writing/judging KB content and tuning retrieval quality.
- **Prune stale docs → `docs-sync` (Sonnet).** The "prepare handover" doc-prune step (step 1 below): reconciling `CLAUDE.md`/`TODO.md`/`DESIGN_NOTES.md`/`README.md` with what changed and converting relative dates to absolute. Hand it a summary of what changed this session + today's date. **Keep on the main thread:** design/direction decisions (it reconciles, it doesn't set direction).
- **Verify a previewable change → `build-verify` (Sonnet, read-only).** After a change the Next.js dev server (port 3000) can render/serve/log, delegate the build + preview-drive + console/network inspection. It reports file:line + evidence and **cannot edit** — you make any fix it surfaces. Skip it (and don't delegate) for changes with no runtime surface (pure types, tooling, docs).

Do **not** auto-delegate anything else — design/token work, write-up voice, and chatbot internals stay on the main thread. If a git/KB task is a genuine trivial one-off where a fresh spawn would cost more than doing it inline, use judgment; otherwise default to delegating per this instruction. If a sub-agent isn't in the roster (e.g. it was added mid-session and needs a restart to load), say so and fall back to doing it inline rather than silently skipping the task.

### On "start" (or similar)

1. **Git bootstrap** *(delegate to `git-ops`)*. `git checkout main`, `git pull`, then create and switch to a fresh session branch named `session/<YYYY-MM-DD>` (today's date; append `-b`, `-c`, … if that branch already exists). This matches the existing `session/<date>` convention.
2. **Design context.** Read `DESIGN_NOTES.md` — it is the canonical, distilled form of the Claude design-system handoff, kept in sync with the tokens in `styles/global.css`. Do **not** wait for a zip. Only ingest a raw handoff bundle when the user explicitly says a *new/updated* design handoff has arrived; in that case, read the zip they provide, then re-distill the changes into `DESIGN_NOTES.md` + the relevant tokens rather than leaving the site pointed at a binary. Raw handoff zips are not committed to the repo (the distilled text is the source of truth).
3. **Get up to speed.** Read `TODO.md` (the living checklist + decisions log) and skim `README.md` and any other top-level `*.md` touched recently.
4. **Report.** Summarize `TODO.md` — what's done, what's outstanding — and recommend the next low-hanging-fruit item (small, unblocked, high-signal) to tackle this session.

### On "prepare handover" (or similar)

1. **Prune stale docs** *(delegate to `docs-sync`; hand it a summary of what changed + today's date)*. Review `CLAUDE.md`, `TODO.md`, `DESIGN_NOTES.md`, and `README.md` against what actually changed this session; remove or correct anything now stale (finished items, superseded decisions, outdated status lines). Convert relative dates to absolute.
2. **Sync git** *(you write the commit message, then delegate stage/commit/push to `git-ops`)*. Stage and commit all session work with a clear message, ensure the working tree is clean (`git status`), then push the session branch to `origin`. Stop short of opening a PR — the user decides when to merge. Report the branch name and what was committed.

## Architecture

**Framework migration (Astro → Next.js, cutover complete 2026-09-01)**: the codebase was migrated from Astro to **Next.js 15 (App Router)** with **React 19**, TypeScript strict, on the `feature/nextjs-migration` integration branch. **The migration is complete and the cutover merge to `main` has happened**: `feature/nextjs-migration` was fast-forward-merged to `main` and pushed, triggering the production Vercel redeploy, so **production now runs the Next.js build**; see `TODO.md`. The rest of this Architecture section describes the Next.js codebase as it now exists on `main`. The legacy Astro source (`src/pages_astro_legacy/`, `src/components/*.astro`, `src/layouts/`, `src/content.config.ts`, the old `src/lib/chat/enabled.ts`) plus `astro.config.mjs` were **deleted on 2026-09-01**, completing the cutover cleanup. Their leftover presence had been breaking `npm run build`: with a `src/` directory present, Next.js misresolved the app dir to `src/app` in the generated route-type validator (`.next/types/validator.ts`) and the type-check failed. With the tree gone, `next build` is green again.

This is a Next.js 15 (App Router) site, written in TypeScript strict with React 19, deployed on **Vercel** (native Next.js integration, no framework adapter). Most routes are static/SSG; the two on-demand routes are the chatbot endpoint (`app/api/chat/route.ts`) and the contact-form endpoint (`app/api/contact/route.ts`), both Next.js route handlers with `export const runtime = 'nodejs'` and `dynamic = 'force-dynamic'`, bundled as serverless functions. It intentionally ships near-zero JavaScript — there is no UI or animation library, and the interactive features (the chatbot, the contact-form dialog, the theme toggle, the header nav, and scroll reveal) are small, purpose-built **client components** (`components/ChatBot.tsx`, `components/ContactForm.tsx`, `components/ThemeToggle.tsx`, `components/Header.tsx`, `components/ScrollReveal.tsx`), not a component/animation library; everything else stays a server component. Any *new* interactive feature should follow the same rule: reach for `'use client'` only where interactivity is truly needed. The scroll-reveal script, now `components/ScrollReveal.tsx` (a single persistent `IntersectionObserver` that toggles the `.js-reveal`/`data-reveal` class pair and re-observes `[data-reveal]:not(.is-revealed)` on each pathname change, so it keeps working across client-side navigation; see `DESIGN_NOTES.md`), is the reference pattern: always progressive enhancement, content fully visible with no JS or `prefers-reduced-motion` set.

**Dev tooling: click-to-source inspector (added 2026-09-01)**: a dependency-free, dev-only "Alt+click to open source in VS Code" inspector, ported from the personal-budget-app implementation. Three pieces. (1) `dev/jsx-dev-runtime.js`, a JSX-dev-runtime shim that stamps each host DOM node with `data-inspect="file:line:col"` via a composed `ref`. React 19 removed `fiber._debugSource`, so the shim reads the `source` arg React still passes to `jsxDEV`; it uses a ref rather than a `data-*` prop so the marker survives SSR hydration. (2) The `webpack` block in `next.config.mjs`, gated on `dev && !isServer`, aliasing `next/dist/compiled/react/jsx-dev-runtime` and `react/jsx-dev-runtime` to the shim and `@real/jsx-dev-runtime` to the real vendored runtime (the `.mjs` config reconstructs `__dirname` and `require.resolve` via `fileURLToPath` + `createRequire`). (3) `components/DevInspector.tsx`, a client component mounted in `app/layout.tsx` only when `NODE_ENV === 'development'` via a dynamic import. It never ships to production (dead-code-eliminated by the NODE_ENV guard and the dev-only alias; verified absent from `.next/static`). Coverage is **client components only**: server-rendered elements carry no marker, because source location is not serialized into the RSC payload, which conveniently covers the interactive parts where iteration happens. If full-page coverage is ever wanted, the noted upgrade path is a dev-only compile-time (SWC/Babel) transform that stamps every element (server components included) at zero production cost; do **not** convert pages to client components just for this. One caveat: the wiring is webpack-only, so do not add `--turbopack` to `next dev` or the inspector silently stops working.

**Content**: `lib/content.ts` (a `fs` + `gray-matter` + `zod` loader, replacing Astro's Content Layer API) defines the `projects` collection with the same schema, the same `_`-prefix exclusion (e.g. `content/projects/_template.md` is a copy-paste template, not published content), the same `draft` filter, and the same date-desc sort. Content moved from `src/content/projects/` to `content/projects/`; the two published write-ups are now `.mdx` (`data-analyst-ai-agent.mdx`, `chat-recommendation-copilot.mdx`), the three drafts plus `_template.md` stay plain `.md`. `app/projects/[slug]/page.tsx` renders individual entries via `generateStaticParams` + `generateMetadata`, rendering MDX through `next-mdx-remote/rsc`, passing a `mdxComponents` map (`{ ...archComponents, CopilotChatDemo }`, the latter added 2026-09-02) so a write-up's MDX body can drop in the arch kit and the animated demo components directly; `app/projects/page.tsx` lists non-draft entries sorted by `date`.

**Layout/components**: every page renders through the root layout `app/layout.tsx`, which owns `<html>`/`<head>`/`<body>` via the Next Metadata API (`metadataBase` from `lib/site.ts`'s `SITE_URL`, a `title` template `"%s — Bobby Muljono"`, canonical URL, OG/Twitter tags — the default OG image is still `/og-default.png`, so `og:image`/`twitter:image` and a `summary_large_image` Twitter card are emitted on every page, pages can still override), the anti-flash inline theme `<script>` in `<head>` (also adds the `js-reveal` class before paint), font preloads, `<Analytics/>`, `<SpeedInsights/>`, and renders `<Header/>` / `<main>{children}</main>` / `<Footer/>` / `<ScrollReveal/>`. Components are React `.tsx` files in `components/` (not `.astro`): `Header` (client component, uses `usePathname` for active-nav styling), `Footer`, `ProjectCard` (the only reusable content component), `ThemeToggle` (client), `ChatBot` (client), `ContactForm` (client). Each component's styles were copied verbatim from the old Astro scoped `<style>` blocks into co-located plain `.css` files, global CSS (not CSS Modules), which is safe because every class name is already uniquely namespaced, matching the design system's namespaced-class approach. There is no client-side routing beyond Next's own App Router; most pages remain static HTML. (The project detail header in `app/projects/[slug]/page.tsx` shows the title with the formatted `date` beneath it; it does not render the `kind` eyebrow or a status line. `kind` still appears on the Work listing cards via `ProjectCard`. Architecture diagrams inside write-ups now use a reusable React component kit at `components/arch/` (`Arch`, `ArchFlow`, `ArchNode`, `ArchArrow`, `ArchNote`, `ArchRow`, `ArchGroup`, `ArchCross`, `ArchTag`, plus the branching `ArchSplit`/`ArchExit`), with the shared `.arch` CSS lifted into `styles/arch.css` (global, token-driven, dark-mode-adaptive); see `DESIGN_NOTES.md`. Because content is MDX, write-ups stay plain markdown while diagrams are components, and React demos or gifs can be dropped straight into a write-up. **Animated demo components (added 2026-09-02)**: a sibling pattern at `components/demos/`, pure-CSS looped-timeline server components (zero client JS, semantic-token-driven so they invert in dark mode, static under `prefers-reduced-motion`) that recreate a product's UI in motion. `CopilotChatDemo.tsx` is the full, 11s-loop recreation of the item-recommendation copilot, embedded as the lead element of `chat-recommendation-copilot.mdx`; `SelectedWorkDemos.tsx` holds two compact mini-demos (`CopilotMiniDemo`, `AnalyticsChatDemo`) used on the Home page's feature cards (see the Home page note below).)

**Design tokens**: all colors, type scale, and spacing are CSS custom properties in `styles/global.css`, imported once by `app/layout.tsx`. Reusable utility classes (`.button` + `--primary`/`--secondary`/`--ghost`/`--sm`, `.card` + `--interactive`/`--wash`, `.tag`/`.tag-list`, `.badge`, `.eyebrow`, `.avatar-placeholder`, `.wrapper`) live there too and are composed in component-level CSS files rather than duplicated. The three brand webfonts are **self-hosted** from `public/fonts/` and declared via `@font-face` in `styles/fonts.css` (also imported by `app/layout.tsx`) — no third-party font request; regenerate the files/CSS with `scripts/fetch-fonts.ps1` if weights/axes change. The reasoning behind the current palette and layout choices (and the named reference sites they're drawn from) is recorded in `DESIGN_NOTES.md` — read and update it when changing visual design, don't just change tokens in isolation. **Standing rule**: for design/layout changes, wait for the user to supply reference sites/samples rather than sourcing inspiration via web search independently.

**Dark mode (added 2026-07-14)**: a `:root[data-theme='dark']` override block in `global.css` remaps only the semantic aliases (plus `--sage-wash`) to warm, forest-derived dark surfaces (never pure black) with the forest-green accent lifted for contrast, so component CSS inverts automatically without per-component changes. An anti-flash inline script in `app/layout.tsx`'s `<head>` applies the stored theme before first paint. New visitors default to **light** and the site does not follow `prefers-color-scheme`; dark only appears once a visitor has explicitly toggled it, persisted in `localStorage` under the `theme` key. The toggle is a slider switch (`role="switch"`, sun/moon knob), now `components/ThemeToggle.tsx`, in the sticky header (`components/Header.tsx`), to the left of the Work link. Two components carry explicit dark-mode overrides: the hero portrait in `app/page.tsx` (drops the bottom mask-fade, restores a full border, adds `--shadow-md`, and applies a slight brightness/contrast filter so the light studio photo seats against the dark page; light mode is unchanged) and the `.arch__group` background in `data-analyst-ai-agent.mdx` (switched from the fixed light token `--oat-raised` to the semantic `--color-surface` so the architecture diagram adapts instead of staying pale in dark mode).
